# G1机器人移动控制修复工具

## 问题描述
机器人进入"控制不了下肢移动"的状态，无论是程序还是直接遥控器都无法控制机器人移动，但是舞蹈等上肢动作可以正常执行。

## 问题原因
这个问题通常是由于机器人进入了非主运控模式导致的，包括：
- 零力矩模式 (Mode 0)
- 阻尼模式 (Mode 1) 
- 位控下蹲 (Mode 2)
- 位控落座 (Mode 3)
- 锁定站立 (Mode 4)
- 平衡下蹲 (Mode 706)

## 解决方案

### 1. 快速诊断
```bash
python3 robot_mode_diagnostic.py
```
这个工具会：
- 检查机器人当前模式
- 诊断问题原因
- 提供修复建议

### 2. 自动修复
```bash
python3 fix_robot_movement.py
```
这个工具会：
- 自动关闭所有相关进程
- 重启机器人服务
- 启动G1客户端
- 等待机器人切换到主运控模式

### 3. 快速修复
```bash
python3 quick_fix_robot.py
```
这个工具会：
- 执行快速修复流程
- 如果失败则显示手动修复指南

### 4. 模式切换
```bash
python3 switch_robot_mode.py
```
这个工具会：
- 强制等待机器人进入主运控模式
- 提供模式切换指导

## 手动修复方法

### 方法1: 使用遥控器
1. 按遥控器上的站立按钮
2. 或者按遥控器上的模式切换按钮
3. 确保机器人处于站立状态

### 方法2: 重启机器人
1. 关闭机器人电源
2. 等待10秒
3. 重新开机
4. 等待机器人完全启动

### 方法3: 启动控制程序
1. 切换到正确目录：
   ```bash
   cd /home/unitree/HongTu/unitree_sdk2_python/example/g1/high_level
   ```
2. 启动G1客户端：
   ```bash
   python3 g1_client_now.py
   ```
3. 等待模式检查完成

## 预防措施

1. **定期检查模式**：使用诊断工具定期检查机器人模式
2. **正确关闭程序**：使用Ctrl+C正确关闭程序，避免强制终止
3. **网络连接**：确保机器人网络连接稳定
4. **服务状态**：定期检查ai_sport等服务是否正常运行

## 常见问题

### Q: 为什么机器人会进入非主运控模式？
A: 可能的原因包括：
- 程序异常退出
- 网络连接中断
- 服务异常
- 机器人安全保护机制触发

### Q: 如何预防这个问题？
A: 建议：
- 使用正确的程序退出方式
- 保持网络连接稳定
- 定期检查机器人状态
- 避免在机器人移动时强制终止程序

### Q: 如果所有方法都失败了怎么办？
A: 最后的手段：
1. 完全重启机器人
2. 检查硬件连接
3. 联系技术支持
